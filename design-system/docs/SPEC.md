# Специфікація документів-рідаутів Nestwood

Читати **перед** створенням будь-якого нового `.html`-рідауту у `research/`, `concept/`, `wireframes/`, `handoff/`. Мета — щоб усі документи проєкту виглядали й читались як один набір, а не як десять різних файлів.

⚠️ **Це шар документів, не продукту.** `doc.css` тут — стиль внутрішніх рідаутів і пітч-матеріалів. Дизайн-система застосунку — це [`../../tokens/`](../../tokens/README.md) і [`../README.md`](../README.md), і вона вирішується окремо. Не переносити ці значення в UI автоматично.

---

## 1. Технічна основа

Один рядок у `<head>`, ніякого інлайн-`<style>`:

```html
<link rel="stylesheet" href="../design-system/docs/doc.css" />
```

- Шлях відносний, тому працює і через `file://`, і через локальний сервер.
- Глибше вкладені документи коригують шлях (`../../design-system/docs/doc.css`).
- **Виняток**: якщо документ треба комусь відправити одним файлом — інлайнити CSS копією, і в комміті зазначити, що це знімок.

`doc.css` уже містить світлу й темну теми: світла за замовчуванням, темна — через `prefers-color-scheme` або `data-theme="dark"` на `<html>`. Нічого додавати не потрібно; тему не хардкодити.

## 2. Каркас сторінки

```html
<div class="shell">
  <aside class="rail">
    <div class="rail-brand">Nestwood<span>НАЗВА ДОКУМЕНТА</span></div>
    <nav><a href="#anchor"><span class="num">1</span> Секція</a>…</nav>
    <div class="railx">…перехід на суміжний документ…</div>
    <div class="rail-foot">дата · джерела…</div>
  </aside>
  <main>
    <div class="masthead">…</div>
    <section class="block" id="anchor">
      <div class="block-head"><span class="block-num mono">01</span><h2 class="block-title">…</h2></div>
      <p class="block-sub">…</p>
      …
    </section>
    <footer class="page">…</footer>
  </main>
</div>
```

Правила:
- **Rail липкий** — навігація доступна з будь-якої точки скролу. Нумерація в `.num` збігається з `.block-num`.
- **Кожен документ лінкує суміжні** через `.railx` (картка в rail) + `.xlink` (пілюля в масхеді). Мінімум один шлях в обидві сторони.
- `<h1 class="title">` — один на документ.
- Заголовки секцій — звичайним регістром, **не CAPS**.

---

## 3. Тон

Два регістри, і їх не змішувати в межах документа:

| | **Внутрішній аналіз** | **Пітч-рідаут** |
|---|---|---|
| Приклад | `concept/personas.html` | `research/research.html` |
| Звертання | третя особа, безособове | друга особа («ти вказуєш…») |
| Задача | показати, на чому стоїть висновок | продати ідею й зняти заперечення |
| Невизначеність | показана явно, маркерами | названа, але не в центрі |

Спільне для обох:
- **Кажемо, що знаємо, і окремо — чого не знаємо.** Гіпотеза, названа гіпотезою, сильніша за факт, що не витримає перевірки.
- **Незручні знахідки лишаються в тексті.** Якщо є контраргумент проти нас — краще, щоб його першими назвали ми.
- Без слів-підсилювачів («революційний», «унікальний»). Замість «унікально» — число й джерело.
- Речення коротке. Абзац — одна думка.

## 4. Маркери надійності

Обов'язкові в аналітичних документах. Легенду ставити на початку.

| | Значення |
|---|---|
| **✓** | Перевірено на першоджерелі — офіційна сторінка власника даних, документація, пряма технічна перевірка |
| **~** | Вторинне джерело — журналістика, огляд, аналітичний сервіс |
| **!** | Слабке джерело — промо/рекламний матеріал, контент-сайт без редакційної відповідальності |
| **?** | Не підтверджено, або наш власний висновок, а не факт із джерела |

У HTML — через `.tag`: `tag-ok` (✓), `tag-hyp` (?), `tag-risk` (ризик/констрейнт), `tag-no` (немає).

**Кожне першоособове джерело підписуємо роком і країною.** Джерело без дати не зараховується. Старше ~3 років — контекст, не доказ.

## 5. Цитати — переклад обов'язковий

Будь-яка неукраїнська цитата йде **з українським перекладом**. Без перекладу цитата шведською чи норвезькою — це декор, а не доказ: її ніхто в команді не прочитає.

```html
<div class="quote">
  <q>Оригінал мовою джерела…</q>
  <span class="tr">Український переклад…</span>
  <span class="attr"><b>Автор</b> · джерело · <span class="fresh">дата</span></span>
</div>
```

- `.quote` — нейтрально, `.quote.no` — інформаційно, `.quote.risk` — те, що суперечить нашій тезі.
- `.tr` сам малює відбивку й префікс `UA` — вручну нічого не додавати.
- `<b>` усередині цитати — акцент на ключовій частині; всередині `.tr` — те саме місце.
- `.fresh` — для свіжих дат, щоб було видно, що це не архів.

## 6. Історія змін — не в документі

**У документі не пишемо, чим він відрізняється від попередньої версії.** Ніяких «було / тепер», «виправлено 2026-08-05», «ревізія 2», «попередня версія стверджувала».

Причини: читач шукає висновок, а не діф; для зовнішньої аудиторії ланцюжок правок читається як нестабільність; а найважливіше — метакоментарі розповзаються по клітинках таблиць і з'їдають сам аналіз.

Де історія живе замість цього:
- **git** — основний журнал;
- **окремий файл-аудит**, коли перевірка сама є результатом (напр. `concept/personas-audit-2026-08-05.md`, `research/research-corrections-2026-08-05.md`). На нього — одне посилання зі статус-рядка документа.

Документ показує **поточний стан і на чому він стоїть**. Якщо твердження змінилось — просто пишемо нове.

## 7. Інвентар компонентів

Спершу перевір, чи є готовий клас — новий CSS додається у `doc.css`, а не в документ.

**Текст і блоки**: `.lede` · `blockquote.pain` · `.block-sub` · `h3.sub` · `.plainlist` · `.footnote`
**Мітки**: `.tag` + `tag-ok|hyp|no|fixed|new|risk` (канонічні) · `.chip*` (синоніми, у нових документах не використовувати) · `.verdict` + `pick|maybe|no` · `.score` + `.s1–.s5` · `.gapnum`
**Таблиці**: `.tablewrap` > `table` (`.wide`) · `tr.grouprow` · `td.rowhead|rowtype|rowpersona|rowlabel|country|num`
**Картки**: `.cardgrid` > `.card` · `.patterncards` > `.pcard` (**патерн**) · `.personagrid` > `.personacard` (**персона** — окремий клас, щоб не конфліктувати з `.pcard`) · `.qgrid` > `.qcard`
**Jobs**: `.mainjob` · `.jobtier` > `.jobcard`
**Виноски**: `.callout` (базовий) · `.alps` · `.answer` · `.riskbox` · `.principlebox` · `.axiscard` · `.decision` · `.exclbox`
**Цитати**: `.voicegroup` > `.quote` > `q` + `.tr` + `.attr`
**Навігація між документами**: `.railx` / `.railx-link` / `.xlink`
**Скріни**: `.shotgroup` > `.shotrow` > `figure.shot`
